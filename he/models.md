# מודלים

LookSee מריצה מודלים לזיהוי אובייקטים שיוצאו ל-ONNX. מודל מותקן כ*חבילה* (bundle): ספרייה תחת `models/` עם קובץ ה-ONNX ומניפסט. ה-API מגלה חבילות בזמן ריצה, צמתי Detect בוחרים ביניהן, ושירות ההסקה (inference) טוען מודל פעם אחת ומשתף אותו בין מצלמות.

## מבנה החבילה

```text
models/
├── ppe-helmets/
│   ├── manifest.json
│   └── model.onnx
└── road-objects/
    ├── manifest.json
    └── model.onnx
```

שם הספרייה הוא מזהה המודל. הוא יכול להכיל אותיות לטיניות קטנות, ספרות, `-` ו-`_`, עד 64 תווים. חבילות נחשבות בלתי-משתנות: החליפו מודל בהוספת ספרייה חדשה ולא בדריסת קבצים במקום, מכיוון ש-workers פעילים שומרים על הגרסה שטענו.

`models/` מחוברת כ-bind mount לקריאה בלבד לקונטיינרים `api` ו-`inference`. חבילה חדשה מופיעה ב-Studio בבקשה הבאה; אין צורך באתחול מחדש. קובצי המודל מוחרגים מהמאגר באמצעות `.gitignore`.

## מניפסט

```json
{
  "name": "Safety gear (PPE)",
  "labels": ["head", "helmet", "vest"],
  "recommended_confidence_threshold": 0.4,
  "events": {
    "head": "NO_HELMET_DETECTED"
  }
}
```

| שדה | נדרש | משמעות |
| --- | --- | --- |
| `labels` | כן | המחלקות שהמודל מפיק, כרשימה לפי סדר מזהי המחלקות או כאובייקט שממפה מזהי מחלקות (`"0"`, `"1"`, …) לתוויות. המזהים חייבים להיות רציפים מאפס והתוויות ייחודיות. |
| `name` | לא | שם התצוגה ב-Studio, 1 עד 128 תווים. ברירת המחדל היא המזהה כשהתווים `-` ו-`_` מוחלפים ברווחים והאות הראשונה של כל מילה רישית. |
| `recommended_confidence_threshold` | לא | ערך בין 0 ל-1 ש-Studio מציע כשהמודל נבחר. |
| `events` | לא | דריסות לאירוע שתווית מפיקה. מחרוזת נותנת שם לסוג האירוע; `null` פירושו שהתווית אינה מפיקה אירוע. המפתחות חייבים להיות תוויות מ-`labels`. |

שדות לא מוכרים נדחים, כך ששגיאת הקלדה בשם שדה מדווחת במקום שיתעלמו ממנה.

## מתוויות לאירועים

כל תווית הופכת לסוג אירוע אלא אם המניפסט קובע אחרת. התווית מומרת לאותיות רישיות, רצפים של תווים שאינם אותיות או ספרות הופכים ל-`_`, תווית שמתחילה בספרה מקבלת את הקידומת `CLASS_`, ו-`_DETECTED` מתווסף בסוף:

| תווית | סוג אירוע |
| --- | --- |
| `helmet` | `HELMET_DETECTED` |
| `space-empty` | `SPACE_EMPTY_DETECTED` |
| `trafficLight-Red` | `TRAFFICLIGHT_RED_DETECTED` |
| `9mm` | `CLASS_9MM_DETECTED` |

סוגי האירועים הם מה שהשדה **Events** של צומת Detect והתנאי **event kind** של If / Else מציעים. השתמשו ב-`events` במניפסט כדי לתת לתווית שם ברור יותר, או כדי להשתיק מחלקות רקע כמו `other`:

```json
"events": { "other": null, "head": "NO_HELMET_DETECTED" }
```

שתי תוויות שמנורמלות לאותו סוג אירוע, כמו `space-empty` ו-`space_empty`, מתמזגות לאירוע אחד; תנו לאחת מהן שם מפורש.

## ייצואי ONNX נתמכים

שירות ההסקה בוחר מתאם לפי שמות הקלט והפלט של גרף ה-ONNX, לא לפי שם הקובץ. שני מבני ייצוא של D-FINE נתמכים:

| ייצוא | קלטים | פלטים | הערות |
| --- | --- | --- | --- |
| Deploy | `images` (float, N×3×H×W), `orig_target_sizes` (int64, N×2) | `labels`, `boxes`, `scores` | הייצוא המומלץ. הפריימים מותאמים בשיטת letterbox לקלט הריבועי של המודל והתיבות ממופות בחזרה לפיקסלי הפריים. |
| Raw | קלט תמונה אחד | `logits`, `pred_boxes` | ייצוא גרף האימון. העיבוד שלאחר ההסקה משקף את מעבד-הפלט הרשמי של D-FINE. |

מודל עם כל חתימה אחרת נדחה כשה-worker מופעל, והמצלמה עוברת ל-**Error** עם הסיבה *unsupported ONNX signature*.

לייצוא checkpoint של D-FINE, השתמשו בכלי הייצוא של [מאגר D-FINE](https://github.com/Peterande/D-FINE) עם גרף ה-deploy מופעל, שמרו על שמות הקלט והפלט שבברירת המחדל, והניחו את הקובץ שנוצר בשם `model.onnx`. כל גודל של D-FINE עובד; מודלים בגודל בינוני מאזנים היטב בין דיוק לעלות מעבד עבור כמה מצלמות.

## ספקי ביצוע

ONNX Runtime בוחר את ספק הביצוע (execution provider) הזמין הראשון בסדר הזה: CUDA, CoreML, CPU. אימג' ההסקה המפורסם מכיל את גרסת ה-CPU. עבור מעבדי GPU של NVIDIA, בנו את האימג' עם התוסף `gpu` כמתואר ב[פריסה](deployment.md#הסקה-על-gpu).

בקונטיינר עם מכסת CPU, שירות ההסקה מגביל את מספר החוטים (threads) של ONNX Runtime למכסה, כדי שכמה workers לא יעמיסו על המארח מעבר ליכולתו. `INFERENCE_CPUS` ב-`.env` קובע מכסה זו.

## זיהוי ומעקב

כל worker של מצלמה מפענח את הזרם, שומר את הפריים החדש ביותר ומריץ את המודל בקצב **Checks per second** (בדיקות לשנייה) של צומת Detect. זיהויים מתחת ל-**Confidence** (סף הביטחון) של הצומת נזרקים לפני המעקב. לאחר מכן ByteTrack מקצה מזהה מעקב שנשמר בין בדיקות למשך כשלוש שניות של היעלמות מהעין, מה שמאפשר ל-Line crossing ול-Dwell לעקוב אחר אובייקט.

הנחיות לשתי הגדרות ה-Detect:

- **Confidence**: התחילו מההמלצה שבמניפסט. ערכים נמוכים תופסים יותר ומייצרים יותר אזעקות שווא; העלו אותו כשהתראות מופעלות על צללים או השתקפויות.
- **Checks per second**: 1 עד 2 מספיקים לתרחישי נוכחות ואזור; 4 עד 8 לספירת אנשים שחוצים קו או כלי רכב מהירים. כל בדיקה עולה הרצת מודל אחת על ה-CPU או ה-GPU.

## מהיכן להשיג מודלים

LookSee מסופקת בלי מודלים, והמאגר אינו מאחסן מודלים. אמנו או כווננו (fine-tune) מודל D-FINE על המחלקות שלכם, ייצאו אותו כמתואר לעיל וכתבו לו מניפסט. חבילה היא ספרייה רגילה, ולכן אפשר להעתיק אותה בין מכונות או לשמור אותה באחסון משלכם.
