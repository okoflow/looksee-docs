# מצלמות

צומת Camera אומר ל-LookSee מהיכן מגיעים הפריימים. MediaMTX קולט כל מקור, חושף אותו לשירות ההסקה (inference) כנתיב RTSP אחד לכל מצלמה, ומגיש את אותו זרם לדפדפנים דרך WebRTC עבור המוניטור החי.

## סוגי מקור

| סוג מקור | שדה | כיצד הוא נקלט |
| --- | --- | --- |
| **RTSP** | כתובת `rtsp://` או `rtsps://` | MediaMTX מושך את הזרם לפי דרישה. רוב מצלמות ה-IP וה-NVR. |
| **RTMP** | כתובת `rtmp://` או `rtmps://` | MediaMTX מושך את הזרם לפי דרישה. |
| **SRT** | כתובת `srt://` | MediaMTX מושך את הזרם לפי דרישה. |
| **Browser webcam** | אין | מצב פרסום (publisher). Studio מפרסם את מצלמת הדפדפן דרך WebRTC (WHIP) אל MediaMTX. |
| **WHEP** | כתובת `http://`, `https://`, `whep://` או `wheps://` | MediaMTX מושך נקודת קצה WebRTC מרוחקת. |
| **File** | מפתח נכס (asset key) | וידאו מספריית הנכסים נשמר במטמון מקומי ומנוגן בלולאה כזרם חי. |

מקורות משיכה (pull) פועלים לפי דרישה: MediaMTX מתחבר למקור כששירות ההסקה או דפדפן מבקשים את הנתיב, ומתנתק עשר שניות אחרי שהקורא האחרון מתנתק. פרטי הגישה למקור נכנסים לתוך ה-URL, `rtsp://user:password@192.168.1.30:554/stream1`, ונשארים על השרת.

## RTSP, RTMP ו-SRT

הזינו את ה-URL שהמצלמה או המקודד שלכם מפרסמים. הערות להגדרות נפוצות:

- השתמשו בזרם המשנה (substream) של המצלמה (720p או פחות) ולא בזרם הראשי. הזיהוי רץ בכמה פריימים לשנייה ואינו מרוויח מ-4K, בעוד שפענוח 4K עולה במשאבי מעבד.
- H.264 מתפענח בכל מקום. H.265 עובד לזיהוי, אבל דפדפנים אינם מנגנים אותו דרך WebRTC, ולכן המוניטור החי נשאר שחור בזמן שההתראות ממשיכות להגיע.
- MediaMTX מושך RTSP דרך TCP. אם מצלמה מציעה UDP בלבד, הציבו אותה מאחורי ממסר (relay) שמדבר TCP.
- מצלמה ברשת אחרת צריכה להיות נגישה מהמכונה שמריצה את LookSee; הדפדפן לעולם אינו מתחבר למצלמה ישירות.

## מצלמת הרשת של הדפדפן

למצלמה מסוג מקור **Browser webcam** אין URL. כשתהליך העבודה רץ והעורך או המוניטור פתוחים, Studio מבקש הרשאה להשתמש במצלמת הרשת ומפרסם אותה אל MediaMTX מהדפדפן. המוניטור מציג למצלמות אלה כפתור **Publish** ו-**Stop publish**. סגירת הכרטיסייה עוצרת את הזרם; המצלמה חוזרת ל-**Pending** עד שדפדפן מפרסם שוב.

הדפדפן מפרסם אל `WEBRTC_HOST_IP` בפורט `8889` וזקוק לפורט ה-ICE `8189/udp` פתוח; ראו [רשת](#רשת).

## קובצי וידאו

מצלמת **File** מנגנת אובייקט מספריית הנכסים בלולאה, מה שמועיל לבדיקת תהליך עבודה מול הקלטה. ספריית הנכסים (asset library) היא bucket תואם S3. סטאק ה-compose כולל אחד משלו, השירות `storage` המבוסס על RustFS עם ה-volume בשם `storage_data`, ויוצר את ה-bucket בהפעלה; הגדירו את משתני `S3_*` כדי להשתמש במקום זאת בנקודת קצה חיצונית כמו Cloudflare R2 או MinIO. בלי bucket מוגדר, הבורר **Assets** ונקודות הקצה `/assets` מושבתים; כשה-bucket מוגדר אך אינו נגיש, הם מחזירים `503`.

קבצים מועלים דרך Studio או `POST /assets`. בהפעלה, ה-API מוריד את האובייקט אל ה-volume של מטמון המדיה, ש-MediaMTX קורא כדי לנגן את הקובץ בלולאה באמצעות ffmpeg. מפתחות אובייקט מוגבלים לאותיות, ספרות, `.`, `_`, `-` ו-`/` מכיוון שהם מגיעים לתוך פקודת ה-ffmpeg הזו.

## MediaMTX

MediaMTX רץ כשירות `mediamtx` עם התצורה ב-`docker/mediamtx/mediamtx.yml`. LookSee מנהלת את הנתיבים שלו דרך API הבקרה בפורט `9997`; הקובץ עצמו קובע רק פרוטוקולים ואימות:

- RTSP ב-`8554` דרך TCP; WebRTC ב-`8889` עם ICE ב-`8189/udp`. מאזיני RTMP, HLS ו-SRT כבויים, מה שאינו משפיע על משיכה ממקורות RTMP או SRT.
- האימות מואצל ל-API: MediaMTX קורא ל-`/internal/media/auth` עבור כל קורא, מפרסם ובקשה ל-API הבקרה. שירות ההסקה וה-API משתמשים במשתמש השירות, `MTX_MEDIA_USER` עם `MTX_MEDIA_PASSWORD`; דפדפנים מציגים הרשאה קצרת-חיים למצלמה אחת שהונפקה על ידי ה-API. הפרטים ב[אבטחה](security.md#גישה-למדיה).
- API הבקרה פתוח לטווחי כתובות loopback ורשת פרטית בלי אימות; compose מאגד אותו ל-`127.0.0.1`.

לכל מצלמה יש נתיב בשם מזהה המצלמה שלה. שירות ההסקה קורא מ-`rtsp://mediamtx:8554/<camera id>` ודפדפנים מנגנים `http://<WEBRTC_HOST_IP>:8889/<camera id>/whep`.

## רשת

וידאו חי מגיע לדפדפן דרך WebRTC, שזקוק ליותר מפורט web פתוח:

| פורט | פרוטוקול | מי מתחבר |
| --- | --- | --- |
| `8889` | TCP | דפדפנים, לאיתות (signalling) וניגון WebRTC (WHEP) ולפרסום מצלמת רשת (WHIP) |
| `8189` | UDP | דפדפנים, למדיה של WebRTC (ICE) |
| `8554` | TCP | מקודדים שדוחפים RTSP אל הנתיב של מצלמת **Browser webcam** (מצב פרסום); לא נדרש למקורות משיכה |

`WEBRTC_HOST_IP` חייב להיות הכתובת שדפדפנים יכולים להגיע אליה: `127.0.0.1` על מחשב נייד, כתובת ה-LAN על שרת. MediaMTX מפרסם אותה במועמדי ICE; ערך שגוי מביא למוניטור שמתחבר ואז מציג **Connection disconnected**. [פריסה](deployment.md) מכסה פרוקסי הפוך (reverse proxy) ו-TLS.

## מצב המצלמה

המוניטור מציג את תג המצב ליד שם המצלמה, ורשימת תהליכי העבודה מציגה אותו לכל תהליך עבודה.

- **Pending** (**Starting** במוניטור): ה-worker מופעל. במקורות משיכה הפריים הראשון מגיע בדרך כלל בתוך כמה שניות; שירות ההסקה מוותר אחרי `FIRST_FRAME_TIMEOUT_SECONDS` (30 שניות) ומדווח על שגיאה.
- **Active** (**Live** במוניטור): פריימים זורמים.
- **Error**: הזרם נכשל או נתקע ל-30 שניות. ה-API מנסה שוב עם השהיה שמוכפלת מ-30 שניות ועד 5 דקות. הסיבה מוצגת במוניטור ובלוגים של `api` ו-`inference`.
- **Off**: תהליך העבודה עצור.

[פתרון בעיות](troubleshooting.md) מפרט את הסיבות הנפוצות ל-**Pending** ול-**Error**.
