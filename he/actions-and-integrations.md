# פעולות ואינטגרציות

פעולות הן הצמתים שבסוף תהליך העבודה: הן הופכות אירוע להתראה, לתמונת מצב או להודעה למערכת חיצונית. פעולות שמתקשרות עם שירות מאמתות באמצעות אישור גישה (credential) השמור ב-LookSee.

## אישורי גישה

העמוד **Credentials** מפרט אישורי גישה שמורים עם שם, סוג ותקציר לא-סודי כמו מארח ה-SMTP או הדומיין של ה-webhook. **New credential** מבקש **Name**, **Type** ואת השדות של סוג זה. הסוד עצמו מוצפן במפתח שנגזר מסוד המופע ואינו מוצג שוב לעולם; עריכת אישור גישה בלי להזין סוד חדש שומרת על הסוד הקיים.

| סוג | בשימוש על ידי | שדות ה-payload |
| --- | --- | --- |
| `telegram_bot` | Telegram | `bot_token` |
| `discord_webhook` | Discord | `webhook_url` |
| `slack_webhook` | Slack (Enterprise) | `webhook_url` |
| `smtp` | Email | `host`, `port` (ברירת מחדל 587), `username`, `password`, `from_address`, `starttls` (פעיל כברירת מחדל) |
| `mqtt` | MQTT | `host`, `port` (ברירת מחדל 1883), `username`, `password` |

פעולות מפנות לאישור גישה לפי מזהה ובודקות את סוגו כשתהליך העבודה מופעל: פעולת Telegram עם אישור גישה של SMTP נכשלת ב-**Run** עם `credential_type_mismatch`. אישורי גישה נפתרים בזמן מסירת ההודעה, ולכן החלפת אסימון חלה על תהליכי עבודה רצים מיידית.

## תבניות הודעה

פעולות Telegram, Discord, Slack, דוא"ל ו-MQTT מעצבות את הטקסט שלהן מתבנית עם מצייני המיקום הבאים:

| מציין מיקום | ערך |
| --- | --- |
| `{kind}` | סוג האירוע, כמו `HELMET_DETECTED` |
| `{camera_id}` | מזהה המצלמה |
| `{ts}` | זמן האירוע בפורמט ISO 8601 |
| `{count}` | כמה זיהויים הפיקו את האירוע |
| `{snapshot_url}` | נתיב תמונת המצב כאשר Snapshot רץ קודם לכן, אחרת ריק |

תבנית ההודעה שבברירת המחדל היא `[{kind}] camera={camera_id} at {ts}`. תבנית עם מציין מיקום לא מוכר נשלחת כפי שנכתבה ואזהרה נרשמת בלוג.

## Alert

רושמת את האירוע בהיסטוריית ההתראות ומציגה אותו במוניטור. שדות: `severity` (`info`, `warning`, `critical`) ו-`cooldown_seconds` (זמן צינון) בשניות (0 עד 3600, ברירת מחדל 30). בתוך זמן הצינון, חזרות באותה מצלמה נזרקות; `0` רושם כל אירוע. התראות הן הפעולה היחידה עם היסטוריה בתוך LookSee; [ניטור והתראות](monitoring-and-alerts.md) מכסה אותה.

## Snapshot

שומרת את הפריים האחרון של המצלמה כ-JPEG, עם הזיהויים מצוירים עליו כאשר `annotate` פעיל (ברירת המחדל). Snapshot היא הפעולה היחידה שיש לה פלט: חברו אחריה את הפעולות שאמורות לשאת את התמונה. הן מקבלות `snapshot_url` לתבניות ול-payloads, ו-Telegram, Discord, Slack ודוא"ל מצרפים את התמונה עצמה.

## Webhook

שולחת את האירוע כ-JSON לכתובת URL בשיטה שנבחרה (`POST` כברירת מחדל, `GET` או `PUT`). לא נדרש אישור גישה; שימו אסימון בתוך ה-URL אם המקבל דורש אחד. הבקשה פוקעת אחרי חמש שניות, ותגובה שאינה 2xx נרשמת בלוג ואינה מנוסה שוב. ה-payload מתועד ב-[API](api.md#ה-payload-של-webhook).

## Telegram

שולחת הודעה, או תמונה עם כיתוב כשתמונת מצב זמינה, לצ'אט. צרו בוט באמצעות [@BotFather](https://t.me/botfather) של Telegram, שמרו את האסימון שלו כאישור גישה מסוג `telegram_bot`, הוסיפו את הבוט לצ'אט היעד והזינו את מזהה הצ'אט בפעולה. לצ'אט פרטי, שלחו הודעה לבוט קודם וקראו את מזהה הצ'אט מ-`https://api.telegram.org/bot<token>/getUpdates`.

## Discord

מפרסמת לערוץ דרך webhook נכנס. צרו את ה-webhook בהגדרות האינטגרציות של הערוץ, שמרו את כתובתו כאישור גישה מסוג `discord_webhook` והגדירו את תבנית ההודעה. Discord מגביל הודעות ל-2000 תווים; טקסטים ארוכים יותר נקטמים.

## Slack

מהדורת Enterprise. מפרסמת לערוץ דרך webhook נכנס של Slack השמור כאישור גישה מסוג `slack_webhook`, עם אותם מצייני מיקום של תבנית.

## Email

שולחת הודעה דרך SMTP עם תבנית נושא ותבנית גוף ומצרפת את תמונת המצב כשיש אחת זמינה. שמרו את השרת כאישור גישה מסוג `smtp`. `starttls` משדרג את החיבור לאחר ההתחברות, כפי שפורט 587 מצפה; השולח הוא `from_address`, או `username` כשהוא ריק. שדה: `to`, כתובת אחת או רשימה מופרדת בפסיקים שהשרת שלכם מקבל.

## MQTT

מפרסמת לנושא (topic) אצל broker השמור כאישור גישה מסוג `mqtt`. שדות: `topic` (ברירת מחדל `looksee/events`) ו-`payload_template`. תבנית ריקה מפרסמת את אותו JSON כמו ה-webhook; תבנית מפרסמת את הטקסט המעובד שלה. החיבורים פוקעים אחרי חמש שניות.

## התנהגות המסירה

- פעולות רצות לפי סדר הגרף לכל אירוע שמגיע אליהן. פעולה שנכשלת רושמת את השגיאה בלוג ואינה עוצרת את הפעולות האחרות.
- כל פעולה רצה לכל היותר פעם אחת לכל אירוע, גם כששני ענפים מובילים אליה.
- סודות לעולם אינם מופיעים בלוגים; כשלי מסירה נרשמים עם הפעולה והסטטוס בלבד.
- בקשות יוצאות משתפות מאגר חיבורים אחד ויוצאות ישירות מקונטיינר ה-API; הגדירו את הפרוקסי או חומת האש בהתאם.
