# פתרון בעיות

תסמינים, סיבות סבירות ומה לבדוק. רוב התשובות נמצאות בלוגים:

```bash
docker compose logs -f api inference mediamtx studio
```

## מצלמה נשארת Pending

שירות ההסקה (inference) לא קיבל פריים ראשון.

- **השרת אינו מגיע למצלמה.** בדקו מהמארח באמצעות `ffprobe rtsp://user:password@camera/stream`. זה שהדפדפן מגיע למצלמה אינו מוכיח דבר; השרת הוא שמושך אותה.
- **המצלמה מדברת RTSP דרך UDP בלבד.** MediaMTX מושך דרך TCP. הפעילו TCP במצלמה או השתמשו בממסר.
- **פרטי גישה או נתיב שגויים** ב-URL. MediaMTX רושם בלוג את שגיאת המקור.
- **הפריים הראשון לקח יותר מ-30 שניות.** העלו את `FIRST_FRAME_TIMEOUT_SECONDS` למצלמות איטיות.
- **מצלמת Browser webcam בלי מפרסם.** פתחו את המוניטור של תהליך העבודה בדפדפן ואשרו גישה למצלמה; המצלמה מופעלת כשדפדפן מפרסם.

## מצלמה מציגה Error

המוניטור והלוג של `inference` מציגים את הסיבה.

- **no frames from stream for 30s**: הזרם נתקע. המצלמה מתחברת מחדש בעצמה וה-API מנסה שוב עם השהיה גדלה עד חמש דקות; תקנו את הרשת או את המצלמה אם זה חוזר.
- **unsupported ONNX signature**: ייצוא המודל אינו אחד ממבני D-FINE הנתמכים. ראו [מודלים](models.md#ייצואי-onnx-נתמכים).
- **model not found**: החבילה נעלמה או שה-mount של `models/` חסר.

## המוניטור אינו מציג וידאו

התראות מגיעות אבל התמונה שחורה או מציגה **Connection disconnected**.

- **`WEBRTC_HOST_IP` שגוי.** הוא חייב להיות הכתובת שהדפדפן יכול להגיע אליה. הערך מוטבע במועמדי WebRTC; `127.0.0.1` עובד רק על השרת עצמו.
- **פורט UDP `8189` חסום** בין הדפדפן לשרת. מדיית WebRTC אינה עוברת דרך פרוקסי ה-HTTP.
- **הזרם הוא H.265.** דפדפנים אינם מנגנים אותו דרך WebRTC. העבירו את המצלמה ל-H.264 או השתמשו בזרם המשנה; הזיהוי ממשיך לעבוד בכל מקרה.
- **No active stream** במצלמת Browser webcam פירושו שעדיין אין מפרסם.
- **מקורות שונים.** אם Studio ו-MediaMTX מוגשים בסכמות שונות (Studio ב-`https`, MediaMTX ב-`http`), הדפדפן חוסם את החיבור. העבירו את שניהם דרך פרוקסי, כמו ב[פריסה](deployment.md#tls-עם-פרוקסי-הפוך).

## הגישה למצלמת הרשת נדחית

דפדפנים מאפשרים `getUserMedia` רק ב-`localhost` או דרך HTTPS. הגישו את Studio דרך TLS למשתמשים מרוחקים, ובדקו את הרשאות האתר בדפדפן אחרי בקשה שנדחתה.

## מודל חסר בצומת Detect

- ספריית החבילה חייבת להכיל גם `manifest.json` וגם `model.onnx`.
- המניפסט נכשל בתיקוף: שדה לא מוכר, תוויות כפולות, פערים במזהי המחלקות, או מפתח `events` שאינו תווית. הלוג של `api` מציין את הבעיה.
- שם הספרייה מכיל תווים שאינם אותיות לטיניות קטנות, ספרות, `-` ו-`_`.

## Run נכשל

**Run** מציג הודעה וממקד את הצומת שאליו היא מתייחסת.

- **סטטוס 402, `feature_not_licensed`**: הגרף מכיל Count, Line crossing, Dwell או Slack בלי רישיון. ראו [מהדורת Enterprise](enterprise.md).
- **סטטוס 422** עם קוד: הגרף אינו יכול לרוץ כפי שצויר. [טבלת התיקוף](nodes.md#תיקוף) מסבירה כל קוד; הנפוצים הם מצלמה בלי צומת Detect, צומת Detect בלי מודל ופעולה בלי אישור גישה.

## העלאת וידאו נכשלת

העלאה דרך **Assets** או הפעלת מצלמת File מחזירה `503` עם *Video storage is unavailable*. השירות `storage` אינו במצב `healthy`, השירות `storage-init` לא יצר את ה-bucket, או שמשתני `S3_*` מצביעים על נקודת קצה שה-API אינו יכול להגיע אליה. בדקו את `docker compose ps storage` ואת `docker compose logs storage-init`.

## התראות אינן נמסרות

- **פעולת Alert מופעלת אבל Telegram, Discord, דוא"ל, MQTT או Slack שותקים.** אישור הגישה חסר, מסוג שגוי, או שהשירות דחה את הבקשה. `GET /deliveries?status=failed` מציג את השגיאה האחרונה של כל משלוח שנכשל, ו-`POST /deliveries/{id}/retry` שולח אותו שוב; הלוג של `api` רושם כל כשל בלי הסוד.
- **הודעות מגיעות באיחור.** משלוח שנכשל בפסק זמן או בשגיאת שרת מנוסה שוב עם השהיה גדלה של עד חמש דקות; היעד לא היה נגיש בינתיים.
- **Telegram** זקוק למזהה של צ'אט שהבוט חבר בו; שלחו לבוט הודעה קודם.
- **Email** זקוק לשרת שמקבל את `from_address`; ספקים רבים דורשים STARTTLS בפורט 587.
- יעדי **Webhook** חייבים לענות בתוך חמש שניות; תגובת `5xx`, `408` או `429` מנוסה שוב, כל שגיאה אחרת לא.
- **שום דבר לא מופעל.** בדקו שסוג האירוע שנבחר ב-Detect הוא סוג שהמודל מפיק, ושאין מסנן ששולח הכול ל-**Else**.

## יותר מדי או פחות מדי התראות

- כל אירוע מגיע לגרף; **זמן הצינון של האירועים** (`EVENT_COOLDOWN_SECONDS`) רק מדלל את הפיד החי ואינו מגביל פעולות.
- ה-**cooldown** של פעולת Alert מדחיק חזרות לכל מצלמה; `0` רושם הכול.
- מסנן **Debounce** נותן לכל ענף חלון זמן משלו.
- העלו את **Confidence** כשצללים או השתקפויות מפעילים זיהויים.

## תמונות מצב חסרות

- פעולת Snapshot חייבת לבוא בגרף לפני הפעולות שמשתמשות בה.
- הפריים האחרון של מצלמה נשמר למשך `LAST_FRAME_TTL_SECONDS` (10 שניות). למצלמה שזה עתה נעצרה אין פריים לצלם.
- קובצי תמונות המצב נמצאים ב-volume בשם `api_snapshots`; ה-URL בהתראה הוא יחסי למקור ה-API.

## מסנני Schedule מופעלים בזמן הלא נכון

לוחות זמנים משתמשים ב-`EVENT_TIMEZONE`, שברירת המחדל שלו UTC. הגדירו אותו לאזור הזמן IANA של האתר, למשל `America/Chicago`, ואתחלו את ה-API.

## סיסמת בעלים שנשכחה

אין תהליך איפוס. הסירו את שורת הבעלים והריצו את ההגדרה הראשונית שוב; תהליכי עבודה, אישורי גישה והתראות נשמרים.

```bash
docker compose exec postgres psql -U looksee -d looksee -c "DELETE FROM users;"
```

> [!WARNING]
> עד שתשלימו שוב את עמוד ההגדרה הראשונית, כל מי שיכול להגיע ל-Studio יכול לתבוע את המופע לעצמו.

## שימוש גבוה ב-CPU

- הורידו את **Checks per second** בצמתי Detect.
- השתמשו בזרמי המשנה של המצלמות ב-720p או פחות; פענוח 4K עולה יותר מהזיהוי.
- תנו לקונטיינר ההסקה יותר מעבדים באמצעות `INFERENCE_CPUS`, או עברו ל-GPU כמתואר ב[פריסה](deployment.md#הסקה-על-gpu).

## פורט כבר בשימוש

שנו את פורט המארח ב-`.env`: `WEB_PORT`, `API_PORT`, `POSTGRES_PORT`, `REDIS_PORT`, `STORAGE_PORT`, `MTX_RTSP_PORT`, `MTX_WEBRTC_PORT`, `MTX_WEBRTC_ICE_PORT`. כאשר `MTX_WEBRTC_PORT` משתנה, הגדירו את `RUNTIME_MEDIAMTX_WEBRTC_URL` בהתאם.
