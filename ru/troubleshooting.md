# Устранение неполадок

Симптомы, вероятные причины и что проверить. Большинство ответов — в
журналах:

```bash
docker compose logs -f api inference mediamtx studio
```

## Камера остаётся в состоянии Pending

Сервис инференса не получил первый кадр.

- **Сервер не достигает камеры.** Проверьте с хоста командой
  `ffprobe rtsp://user:password@camera/stream`. То, что камеру видит браузер,
  ничего не доказывает: поток забирает сервер.
- **Камера говорит RTSP только по UDP.** MediaMTX забирает поток по TCP.
  Включите TCP на камере или поставьте ретранслятор.
- **Неверные учётные данные или путь** в URL. MediaMTX записывает ошибку
  вышестоящего источника в журнал.
- **Первый кадр пришёл позже, чем через 30 секунд.** Для медленных камер
  увеличьте `FIRST_FRAME_TIMEOUT_SECONDS`.
- **Камера Browser webcam без публикующего браузера.** Откройте монитор
  рабочего процесса в браузере и разрешите доступ к камере; камера
  активируется, когда браузер начинает публиковать.

## Камера показывает Error

Причину показывают монитор и журнал `inference`.

- **no frames from stream for 30s**: поток замер. Камера переподключается
  сама, а API повторяет попытки с растущей задержкой до пяти минут; если это
  повторяется, исправьте сеть или камеру.
- **unsupported ONNX signature**: экспорт модели не соответствует ни одному
  из поддерживаемых вариантов D-FINE. См.
  [Модели](models.md#поддерживаемые-экспорты-onnx).
- **model not found**: пакет модели исчез или отсутствует монтирование
  `models/`.

## Монитор не показывает видео

Оповещения приходят, но картинка чёрная или показывает
**Connection disconnected**.

- **Неверный `WEBRTC_HOST_IP`.** Это должен быть адрес, доступный браузеру.
  Значение попадает в кандидаты WebRTC; `127.0.0.1` работает только на самом
  сервере.
- **UDP-порт `8189` заблокирован** между браузером и сервером. Медиапоток
  WebRTC не проходит через HTTP-прокси.
- **Поток в H.265.** Браузеры не воспроизводят его по WebRTC. Переключите
  камеру на H.264 или используйте дополнительный поток; детекция работает в
  любом случае.
- **No active stream** для камеры Browser webcam означает, что никто ещё не
  публикует.
- **Разные origin.** Если Studio и MediaMTX раздаются по разным схемам
  (`https` у Studio, `http` у MediaMTX), браузер блокирует соединение.
  Проксируйте оба, как в разделе
  [Развёртывание](deployment.md#tls-через-обратный-прокси).

## Доступ к веб-камере запрещён

Браузеры разрешают `getUserMedia` только на `localhost` или по HTTPS.
Раздавайте Studio по TLS для удалённых пользователей, а после отклонённого
запроса проверьте разрешения сайта в браузере.

## Модель отсутствует в узле Detect

- Каталог пакета должен содержать оба файла: `manifest.json` и `model.onnx`.
- Манифест не прошёл проверку: неизвестное поле, повторяющиеся метки,
  пропуски в идентификаторах классов или ключ `events`, не являющийся меткой.
  Журнал `api` называет проблему.
- Имя каталога содержит символы помимо строчных латинских букв, цифр, `-` и
  `_`.

## Run завершается ошибкой

**Run** показывает сообщение и выделяет узел, к которому оно относится.

- **Статус 402, `feature_not_licensed`**: граф содержит Count, Line crossing,
  Dwell или Slack без лицензии. См. [Редакция Enterprise](enterprise.md).
- **Статус 422** с кодом: граф не может работать в нарисованном виде.
  [Таблица валидации](nodes.md#валидация) объясняет каждый код; самые
  частые — камера без узла Detect, узел Detect без модели и действие без
  учётных данных.

## Не загружается видео

Загрузка через **Assets** или запуск камеры File отвечает `503` с текстом
*Video storage is unavailable*. Сервис `storage` не в состоянии `healthy`,
сервис `storage-init` не создал бакет, или переменные `S3_*` указывают на
конечную точку, до которой API не достучаться. Проверьте
`docker compose ps storage` и `docker compose logs storage-init`.

## Оповещения не доставляются

- **Действие Alert срабатывает, а Telegram, Discord, электронная почта, MQTT
  или Slack молчат.** Учётные данные отсутствуют, имеют неверный тип, или
  сервис отклонил запрос. `GET /deliveries?status=failed` показывает
  последнюю ошибку каждой неудавшейся доставки, а
  `POST /deliveries/{id}/retry` отправляет её заново; журнал `api`
  фиксирует каждый сбой без секрета.
- **Сообщения приходят с опозданием.** Доставка, упавшая по тайм-ауту или
  ошибке сервера, повторяется с растущей задержкой до пяти минут; всё это
  время получатель был недоступен.
- **Telegram** нужен идентификатор чата, в котором состоит бот; сначала
  напишите боту.
- **Email** нужен сервер, принимающий `from_address`; многие провайдеры
  требуют STARTTLS на порту 587.
- **Webhook**: получатель должен ответить в течение пяти секунд; ответ
  `5xx`, `408` или `429` повторяется, любая другая ошибка — нет.
- **Ничего не срабатывает вообще.** Проверьте, что тип события, выбранный в
  Detect, — один из тех, что производит модель, и что какой-нибудь фильтр не
  отправляет всё в **Else**.

## Слишком много или слишком мало оповещений

- В граф попадает каждое событие; **пауза между событиями**
  (`EVENT_COOLDOWN_SECONDS`) лишь прореживает живую ленту и действия не
  ограничивает.
- **cooldown** действия Alert подавляет повторы по каждой камере; `0`
  записывает всё.
- Фильтр **Debounce** даёт любой ветке своё окно.
- Повышайте **Confidence**, когда детекции срабатывают на тени или отражения.

## Снимки отсутствуют

- Действие Snapshot должно стоять в графе перед действиями, которые его
  используют.
- Последний кадр камеры хранится `LAST_FRAME_TTL_SECONDS` (10 секунд). У
  только что остановившейся камеры нет кадра для снимка.
- Файлы снимков лежат в томе `api_snapshots`; URL в оповещении указан
  относительно origin API.

## Фильтры Schedule срабатывают не в то время

Расписания используют `EVENT_TIMEZONE`, по умолчанию UTC. Задайте часовой
пояс объекта в формате IANA, например `America/Chicago`, и перезапустите API.

## Забыт пароль владельца

Процедуры сброса нет. Удалите строку владельца и пройдите первоначальную
настройку снова; рабочие процессы, учётные данные и оповещения сохраняются.

```bash
docker compose exec postgres psql -U looksee -d looksee -c "DELETE FROM users;"
```

> [!WARNING]
> Пока вы снова не пройдёте страницу первоначальной настройки, экземпляр
> может присвоить любой, кто способен достучаться до Studio.

## Высокая нагрузка на CPU

- Понизьте **Checks per second** на узлах Detect.
- Используйте дополнительные потоки камер с разрешением 720p или ниже;
  декодирование 4K стоит дороже детекции.
- Дайте контейнеру инференса больше CPU через `INFERENCE_CPUS` или перейдите
  на GPU, как описано в разделе [Развёртывание](deployment.md#инференс-на-gpu).

## Порт уже занят

Измените порт хоста в `.env`: `WEB_PORT`, `API_PORT`, `POSTGRES_PORT`,
`REDIS_PORT`, `STORAGE_PORT`, `MTX_RTSP_PORT`, `MTX_WEBRTC_PORT`,
`MTX_WEBRTC_ICE_PORT`. При
изменении `MTX_WEBRTC_PORT` приведите в соответствие
`RUNTIME_MEDIAMTX_WEBRTC_URL`.
