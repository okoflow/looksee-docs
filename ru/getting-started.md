# Начало работы

Эта страница проводит LookSee от чистой машины до входа в Studio с готовой к
использованию моделью детекции. Она использует Docker Compose —
поддерживаемый способ запуска LookSee.

## Требования

- Docker Engine с Docker Compose 2.24 или новее. Docker Desktop подходит для
  macOS и Windows; обычная цель для продуктивной эксплуатации — серверы на
  Linux.
- 64-разрядный процессор x86 или ARM. По умолчанию детекция выполняется на
  CPU; GPU с CUDA необязателен и описан в разделе
  [Развёртывание](deployment.md#инференс-на-gpu).
- Свободные порты `3000` (Studio), `8000` (API), `8554` (RTSP), `8889`
  (WebRTC) и `8189/udp` (WebRTC ICE). PostgreSQL, Valkey и управляющий API
  MediaMTX слушают только петлевой интерфейс.

Файл compose ограничивает ресурсы каждого сервиса. Сервис инференса по
умолчанию получает 4 CPU и 4 ГБ памяти; для большего числа камер или более
крупных моделей увеличьте `INFERENCE_CPUS` и `INFERENCE_MEMORY` в `.env`.

## Установка

```bash
git clone https://github.com/okoflow/looksee.git
cd looksee
cp .env.example .env
```

Откройте `.env` и перед первым запуском задайте два значения:

| Переменная | Значение |
| --- | --- |
| `WEBRTC_HOST_IP` | `127.0.0.1`, когда браузер работает на той же машине. Адрес машины в вашей сети, например `192.168.1.20`, когда вы открываете Studio с другого устройства. По этому адресу браузеры подключаются за живым видео. |
| `POSTGRES_PASSWORD`, `MTX_MEDIA_PASSWORD` | Ваши собственные значения. Значения из примера — заглушки, а пароль MediaMTX виден браузерам, которые загружают Studio. |

Затем соберите и запустите стек:

```bash
docker compose up -d --build
docker compose ps
```

Первая сборка скачивает базовые образы и пакеты Python и Node и занимает
несколько минут. Когда стек готов, `docker compose ps` показывает каждый
сервис как `healthy`: `postgres`, `redis`, `mediamtx`, `api`, `inference` и
`studio`. Одноразовые сервисы `api-migrate` и `media-cache-init` завершаются,
когда выполнят свою работу.

## Создание учётной записи владельца

Откройте `http://<WEBRTC_HOST_IP>:3000`. Пока учётной записи нет, Studio
перенаправляет на страницу первоначальной настройки. Введите адрес
электронной почты, отображаемое имя и пароль не короче восьми символов с
одной цифрой и одной заглавной буквой. Учётная запись становится владельцем
экземпляра, и вы входите в систему.

> [!WARNING]
> Пока владелец не создан, экземпляр может присвоить любой, кто способен
> достучаться до порта `3000`. Создайте учётную запись сразу после первого
> запуска и держите стек в доверенной сети. Остальное описано в разделе
> [Безопасность](security.md).

## Добавление модели детекции

LookSee поставляется без моделей. Модель — это каталог внутри `models/` в
клоне репозитория с двумя файлами:

```text
models/
└── ppe-helmets/
    ├── manifest.json
    └── model.onnx
```

`model.onnx` — модель D-FINE, экспортированная в ONNX. `manifest.json` задаёт
имя модели и её классы:

```json
{
  "name": "Safety gear (PPE)",
  "labels": ["head", "helmet", "vest"],
  "recommended_confidence_threshold": 0.4
}
```

Каталог `models/` монтируется в контейнеры API и инференса только для чтения,
а API обнаруживает новый пакет модели при следующем запросе, так что
перезапуск не нужен. Каждая метка становится типом события, например
`HELMET_DETECTED`. Раздел [Модели](models.md) полностью описывает манифест и
экспорт модели.

## Проверка стека

```bash
curl http://127.0.0.1:8000/health
docker compose logs -f api inference
```

API отвечает `{"status":"ok"}`. Интерактивная документация API доступна по
адресу `http://127.0.0.1:8000/docs`.

## Повседневные команды

```bash
docker compose logs -f studio api inference mediamtx   # follow logs
docker compose stop                                    # stop, keep data
docker compose up -d                                   # start again
git pull && docker compose up -d --build               # upgrade
docker compose down -v                                 # remove everything, including data
```

Рабочие процессы, камеры, учётные данные, оповещения, снимки и секрет подписи
хранятся в именованных томах. `down -v` удаляет их; раздел
[Развёртывание](deployment.md) объясняет, как делать их резервные копии.
