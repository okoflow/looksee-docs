# История изменений

История выпусков LookSee. Версии следуют семантическому версионированию,
даты — это даты выпуска. Изменения в `main`, которые ещё не выпущены,
перечислены в разделе *Unreleased*.

## [Unreleased]

## [0.2.0] - 2026-09-05

Обновление с 0.1.0:

- Задайте `STORAGE_PASSWORD` в `.env`. У `POSTGRES_PASSWORD` и
  `MTX_MEDIA_PASSWORD` больше нет значений из примера, их тоже нужно
  задать; compose не запускается, пока хотя бы одна из трёх переменных
  пуста.
- Смените `MTX_MEDIA_PASSWORD`: версия 0.1.0 передавала его каждому
  браузеру, загружавшему Studio.
- Выполните `docker compose up -d --build`: `api-migrate` применит миграцию
  `0002`, а `storage-init` создаст бакет для видео. Обновляйте API, сервис
  инференса, Studio и MediaMTX вместе: MediaMTX теперь авторизует каждое
  подключение через API.
- События больше не выжидают `EVENT_COOLDOWN_SECONDS` перед попаданием в
  граф. Там, где пауза подавляла повторные действия, добавьте фильтр
  Debounce или паузу действия Alert.
- Профиль compose `docs` и `DOCS_PORT` удалены; документация живёт в этом
  репозитории.

### Добавлено

- Встроенное S3-совместимое видеохранилище: сервис `storage` (RustFS) с
  томом `storage_data`, который compose создаёт и подготавливает, так что
  камеры File работают без внешнего бакета. Переменные `S3_*` по-прежнему
  направляют API на внешний бакет.
- Очередь доставок: сообщения Webhook, Telegram, Discord, Slack, Email и
  MQTT сохраняются в PostgreSQL и повторяются после временных сбоев с
  задержкой, удваивающейся до пяти минут, не более восьми попыток.
  `GET /deliveries` показывает очередь, а `POST /deliveries/{id}/retry`
  ставит неудавшуюся доставку в очередь заново. Запросы Webhook несут
  заголовок `Idempotency-Key`.
- Гранты доступа к медиа на одну камеру: `POST /cameras/{id}/media-access`
  выдаёт пятиминутный токен на чтение или публикацию одной камеры, а
  MediaMTX авторизует каждое подключение через API.
- Ограничение попыток входа и первоначальной настройки: 20 попыток с одного
  клиента и 100 суммарно в минуту, дальше `429` с `Retry-After`.
- Проверка Origin: запросы, изменяющие состояние, и подключения WebSocket,
  чей `Origin` не подходит ни под `CORS_ORIGIN_REGEX`, ни под origin API,
  отклоняются с `403`.
- Непрерывная интеграция запускает линтинг, тесты, проверку миграций,
  сборку Studio и проверку конфигурации compose на каждом pull request, с
  наборами тестов для общих контрактов, API, сервиса инференса и пакета
  Enterprise.
- Документация репозитория: README, руководство для участников, политика
  безопасности, кодекс поведения и формы для issue. Эта документация на
  английском, русском, иврите и корейском языках.

### Изменено

- Пароль медиапользователя MediaMTX — серверный секрет, общий для API,
  сервиса инференса и MediaMTX; Studio его больше не получает.
- `EVENT_COOLDOWN_SECONDS` ограничивает только сообщения `event` живой
  ленты; в граф попадает каждое событие.
- Сбои хранилища отвечают `503` с понятным сообщением вместо внутренней
  ошибки.
- Кадры детекции, не подтверждённые остановленным процессом API,
  обрабатываются заново через минуту, а кадры обрабатываются по одному.
- `.env.example` сгруппирован по сервисам и перечисляет только настройки,
  которые задаёт установка; обязательные пароли пусты.
- Studio поставляет шрифт в комплекте вместо загрузки из Google Fonts,
  сохраняет правки, сделанные во время сохранения, и ведёт ссылкой
  **Documentation** в этот репозиторий.
- MediaMTX 1.20.1.

### Исправлено

- Переключение камеры с RTSP на Browser webcam оставляло MediaMTX забирать
  старый поток; конфигурация пути теперь заменяется, а не дополняется.
- Сессии WebRTC закрываются при уходе с монитора, а сохранение рабочего
  процесса больше не конфликтует с правками, сделанными во время
  сохранения.
- Инструменты линтинга Studio для структуры монорепозитория и
  предупреждение безопасности по зависимости Studio.

## [0.1.0] - 2026-08-06

Первый выпуск.

- Редактор рабочих процессов с узлами Camera, Detect, If / Else, Class,
  Size, Zone, Schedule и Debounce и действиями Alert, Snapshot, Webhook,
  Telegram, Email, MQTT и Discord; Count, Line crossing, Dwell и Slack в
  редакции Enterprise.
- Источники камер по RTSP, RTMP, SRT, WHEP, веб-камеры браузера и видеофайлы
  из S3-совместимой библиотеки файлов, принимаемые через MediaMTX.
- Инференс ONNX для экспортов D-FINE с трекингом ByteTrack на CPU, CUDA или
  CoreML.
- Живой монитор с воспроизведением WebRTC, наложением детекций и зон, лентой
  событий и историей оповещений со снимками.
- Зашифрованное хранилище учётных данных, учётная запись владельца с cookie
  сессий и развёртывание Docker Compose с PostgreSQL и Valkey.
