# Модели

LookSee запускает модели детекции объектов, экспортированные в ONNX. Модель
устанавливается как *пакет модели*: каталог внутри `models/` с файлом ONNX и
манифестом. API обнаруживает пакеты во время работы, узлы Detect выбирают
среди них, а сервис инференса загружает модель один раз и разделяет её между
камерами.

## Структура пакета

```text
models/
├── ppe-helmets/
│   ├── manifest.json
│   └── model.onnx
└── road-objects/
    ├── manifest.json
    └── model.onnx
```

Имя каталога — идентификатор модели. Оно может содержать строчные латинские
буквы, цифры, `-` и `_`, до 64 символов. Пакеты считаются неизменяемыми:
заменяйте модель, добавляя новый каталог, а не перезаписывая файлы на месте,
потому что работающие воркеры сохраняют загруженную версию.

`models/` монтируется только для чтения в контейнеры `api` и `inference`.
Новый пакет появляется в Studio при следующем запросе; перезапуск не
требуется. Файлы моделей исключены из репозитория через `.gitignore`.

## Манифест

```json
{
  "name": "Safety gear (PPE)",
  "labels": ["head", "helmet", "vest"],
  "recommended_confidence_threshold": 0.4,
  "events": {
    "head": "NO_HELMET_DETECTED"
  }
}
```

| Поле | Обязательное | Значение |
| --- | --- | --- |
| `labels` | Да | Классы, которые выдаёт модель: либо список в порядке идентификаторов классов, либо объект, сопоставляющий идентификаторы классов (`"0"`, `"1"`, …) с метками. Идентификаторы идут подряд от нуля, метки уникальны. |
| `name` | Нет | Отображаемое имя в Studio, от 1 до 128 символов. По умолчанию — идентификатор, в котором `-` и `_` заменены пробелами, а каждое слово начинается с заглавной буквы. |
| `recommended_confidence_threshold` | Нет | Значение от 0 до 1, которое Studio предлагает при выборе модели. |
| `events` | Нет | Переопределения события, которое производит метка. Строка задаёт тип события; `null` означает, что метка не производит событий. Ключи должны быть метками из `labels`. |

Неизвестные поля отклоняются, поэтому опечатка в имени поля будет замечена,
а не проигнорирована.

## От меток к событиям

Каждая метка становится типом события, если манифест не говорит иного. Метка
переводится в верхний регистр, последовательности символов, кроме букв и
цифр, становятся `_`, метка, начинающаяся с цифры, получает префикс `CLASS_`,
и добавляется `_DETECTED`:

| Метка | Тип события |
| --- | --- |
| `helmet` | `HELMET_DETECTED` |
| `space-empty` | `SPACE_EMPTY_DETECTED` |
| `trafficLight-Red` | `TRAFFICLIGHT_RED_DETECTED` |
| `9mm` | `CLASS_9MM_DETECTED` |

Типы событий — это то, что предлагают поле **Events** узла Detect и условие
**event kind** узла If / Else. Используйте `events` в манифесте, чтобы дать
метке более понятное имя или заглушить фоновые классы, такие как `other`:

```json
"events": { "other": null, "head": "NO_HELMET_DETECTED" }
```

Две метки, которые нормализуются в один тип события, например `space-empty`
и `space_empty`, сливаются в одно событие; задайте одной из них явное имя.

## Поддерживаемые экспорты ONNX

Сервис инференса выбирает адаптер по именам входов и выходов графа ONNX, а не
по имени файла. Поддерживаются два варианта экспорта D-FINE:

| Экспорт | Входы | Выходы | Примечания |
| --- | --- | --- | --- |
| Deploy | `images` (float, N×3×H×W), `orig_target_sizes` (int64, N×2) | `labels`, `boxes`, `scores` | Рекомендуемый экспорт. Кадры вписываются в квадратный вход модели с сохранением пропорций, а рамки пересчитываются обратно в пиксели кадра. |
| Raw | один вход с изображением | `logits`, `pred_boxes` | Экспорт обучающего графа. Постобработка повторяет официальный постпроцессор D-FINE. |

Модель с любой другой сигнатурой отклоняется при запуске воркера, и камера
переходит в **Error** с причиной *unsupported ONNX signature*.

Чтобы экспортировать чекпоинт D-FINE, используйте инструменты экспорта из
[репозитория D-FINE](https://github.com/Peterande/D-FINE) с включённым графом
deploy, оставьте имена входов и выходов по умолчанию и положите полученный
файл как `model.onnx`. Подходит любой размер D-FINE; средние модели хорошо
балансируют точность и нагрузку на CPU для нескольких камер.

## Провайдеры выполнения

ONNX Runtime выбирает первый доступный провайдер в таком порядке: CUDA,
CoreML, CPU. Опубликованный образ инференса содержит сборку для CPU. Для GPU
NVIDIA соберите образ с дополнением `gpu`, как описано в разделе
[Развёртывание](deployment.md#инференс-на-gpu).

В контейнере с квотой CPU сервис инференса ограничивает число потоков ONNX
Runtime этой квотой, чтобы несколько воркеров не перегружали хост. Квоту
задаёт `INFERENCE_CPUS` в `.env`.

## Детекция и трекинг

Каждый воркер камеры декодирует поток, хранит самый свежий кадр и запускает
модель с частотой **Checks per second** узла Detect. Детекции ниже
**Confidence** узла отбрасываются до трекинга. Затем ByteTrack присваивает
идентификатор трекинга, который сохраняется между проверками примерно три
секунды после потери объекта из виду, что позволяет Line crossing и Dwell
следить за объектом.

Рекомендации по двум настройкам Detect:

- **Confidence**: начните с рекомендации из манифеста. Меньшие значения ловят
  больше и чаще дают ложные тревоги; повышайте порог, когда оповещения
  срабатывают на тени или отражения.
- **Checks per second**: от 1 до 2 достаточно для сценариев присутствия и
  зон; от 4 до 8 — для подсчёта людей, пересекающих линию, или быстрых
  автомобилей. Каждая проверка стоит одного прогона модели на CPU или GPU.

## Где взять модели

LookSee поставляется без моделей, и репозиторий их не размещает. Обучите или
дообучите модель D-FINE на своих классах, экспортируйте её, как описано выше,
и напишите для неё манифест. Пакет модели — обычный каталог, поэтому его
можно копировать между машинами или хранить в своём хранилище.
