# 모니터링과 알림

모든 워크플로에는 모니터 페이지가 있습니다. 탐지 오버레이가 겹쳐진 카메라 실시간 영상, 그래프가 만드는 이벤트의 피드, 알림 기록을 보여 줍니다. 헤더는 **Editor**(편집기)와 **Monitor**(모니터)를 전환하며 **Run**(실행)과 **Stop**(중지) 버튼을 담고 있습니다.

![구역 오버레이와 실시간 이벤트 피드가 표시된 모니터](../images/monitor.png)

## 실시간 보기

영상은 MediaMTX에서 WebRTC로 재생되는 카메라 스트림입니다. 그 위에는 카메라 이름과 상태 배지가 있습니다. 워커가 연결 중이면 **Starting**(시작 중), 프레임이 흐르면 **Live**(라이브), 스트림이 실패하면 이유와 함께 **Error**(오류), 워크플로가 중지되면 **Off**(꺼짐)입니다. 카메라가 여럿인 워크플로에는 카메라 선택기가 표시됩니다.

영상 위에 오버레이가 그려집니다.

- 현재 탐지의 **경계 상자**. 클래스가 레이블로 표시되며, 마지막 탐지 메시지 후 3초가 지나면 사라집니다.
- 그래프의 Zone, Count, Dwell, Line crossing 필터에서 가져온 **구역과 선**. 필터가 무엇을 기준으로 검사하는지 볼 수 있습니다.

유형이 **Browser webcam**인 카메라에는 브라우저 카메라 전송을 시작하는 **Publish**(송출) 버튼이 표시되고, **Stop publish**(송출 중지)가 이를 끝냅니다. 실행 중인 워크플로의 편집기나 모니터를 열면 송출이 자동으로 시작됩니다.

## 이벤트 피드

**Live** 탭은 그래프가 받는 이벤트를 최신순으로 나열하며, 시각, 이벤트 종류, 이벤트를 만든 레이블을 보여 줍니다. 같은 카메라에서 같은 종류가 `EVENT_COOLDOWN_SECONDS` 안에 반복되면 한 번만 표시됩니다. 최근 30개 항목을 유지하고 **Clear**(지우기)가 비웁니다. 피드는 필터를 거치기 전에 그래프로 들어오는 것을 반영하므로, 모델이 기대한 이벤트를 만드는지 확인하는 자리입니다.

## 알림

**Alerts** 탭은 이 워크플로의 Alert 액션이 기록한 알림을 시각, 심각도, Alert 앞에 Snapshot이 실행된 경우 스냅샷 썸네일, 메시지와 함께 나열합니다. 메시지는 사람이 읽기 쉽게 바꾼 이벤트 종류와 카메라 이름으로, 예를 들어 *Pedestrian on Crossing camera*입니다. 각 행에는 삭제 버튼이 있고, API로도 카메라별 또는 워크플로별로 기록을 지울 수 있습니다.

![스냅샷 썸네일이 표시된 Alerts 탭](../images/alerts.png)

심각도는 Alert 노드에서 **info**, **warning**, **critical** 중 하나로 설정합니다. 알림의 **cooldown**(재알림 대기 시간)은 시간 창 안에서 카메라별 반복을 억제하며, `0`은 모든 이벤트를 기록합니다. 알림은 삭제할 때까지 남으므로, 장기간 운영하는 인스턴스는 `DELETE /alerts`로 때때로 정리해야 합니다.

워크플로 페이지가 열려 있는 동안에는 새 알림과 카메라 오류가 Studio 모서리의 알림 메시지로도 표시됩니다.

## 스냅샷

Snapshot 액션은 카메라의 최신 프레임을 JPEG로 저장합니다. **Annotate**(주석)가 켜져 있으면 이미지에 탐지가 그려집니다. 파일은 `api_snapshots` 볼륨에 저장되고 로그인한 사용자에게 `/snapshots/<file>`로 제공됩니다. Snapshot 노드 하류의 알림, 웹훅, Telegram, Discord, Slack, 이메일 메시지가 URL을 받고, 메시징 액션은 이미지 자체를 첨부합니다.

스냅샷은 추론 서비스가 저장한 가장 최근 프레임을 반영하며, 이 프레임은 최대 `LAST_FRAME_TTL_SECONDS`만큼 오래된 것입니다. 카메라가 프레임 생성을 멈췼으면 액션은 경고를 로그에 남기고 건너뜁니다.

## 전달

Webhook, Telegram, Discord, Slack, Email, MQTT 메시지는 이벤트를 만든 프레임에서 바로 보내지 않습니다. 각 메시지는 PostgreSQL에 전달로 저장되고 API 안의 워커가 보냅니다. 워커는 일시적 실패(타임아웃, HTTP `408`, `429`, `5xx`)를 재시도하며, 간격은 시도마다 두 배로 늘어나 최대 5분까지이고 최대 8회 시도합니다. 거부된 요청, 없는 자격 증명, 이미 사라진 스냅샷은 전달을 즉시 실패시킵니다. 전달은 API 재시작 후에도 남으며, 메시지는 최소 한 번 전달되고, 웹훅은 `Idempotency-Key` 헤더에 전달 ID를 담습니다.

Studio는 전달을 표시하지 않습니다. `GET /deliveries?status=failed`는 최근 실패를 마지막 오류와 함께 나열하고, `POST /deliveries/{id}/retry`는 전달을 다시 큐에 넣습니다. [API](api.md#전달)를 참고하십시오.

## 실시간 접근

모니터가 보여 주는 모든 것은 카메라당 하나의 WebSocket인 `/ws/cameras/{camera_id}`에서 옵니다. 스크립트도 같은 스트림을 구독할 수 있으며, 메시지는 [API](api.md#websocket)에 문서화되어 있습니다.
