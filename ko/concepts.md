# 개념

이 페이지는 나머지 문서에서 사용하는 용어를 설명합니다. 워크플로와 노드, 이벤트와 모델이 이벤트를 만드는 방식, 카메라와 실행, 그리고 두 에디션을 다룹니다.

## 워크플로

워크플로는 하나의 분석 작업을 기술하는 그래프입니다. 어떤 카메라를 지켜볼지, 어떤 모델을 실행할지, 어떤 탐지가 중요한지, 그에 대해 무엇을 할지를 담습니다. 워크플로는 Studio에서 만들고 편집하며 API가 저장합니다. 워크플로는 실행 중(**Active**)이거나 중지됨(**Off**) 상태이며, 편집기의 **Run**(실행)이 시작하고 **Stop**(중지)이 중지합니다.

워크플로에는 이름, 선택적인 설명, 그리고 노드와 연결로 이루어진 그래프가 있습니다. 캔버스 주석은 문서화 용도로 추가할 수 있으며 실행되지 않습니다.

## 노드와 연결

노드는 캔버스 위의 상자입니다. 각 노드에는 종류와 필드 집합이 있고, 오른쪽 인스펙터에서 필드를 편집합니다. 노드 종류는 네 가지 역할로 나뉩니다.

| 역할 | 노드 | 목적 |
| --- | --- | --- |
| 소스 | Camera | 프레임이 들어오는 곳 |
| 탐지 | Detect | 어떤 모델을 실행하고 그중 어떤 이벤트를 통과시킬지 |
| 필터 | If / Else, Class, Size, Zone, Schedule, Debounce; Enterprise 에디션의 Count, Line crossing, Dwell | 이벤트를 계속 흘려보낼지 결정 |
| 액션 | Alert, Snapshot, Webhook, Telegram, Email, MQTT, Discord; Enterprise 에디션의 Slack | 이벤트로 무언가를 수행 |

연결은 노드를 왼쪽에서 오른쪽으로 잇습니다. Camera는 정확히 하나의 Detect에 연결됩니다. Detect는 임의 개수의 필터와 액션으로 갈라져 나갑니다. 모든 필터에는 **If**와 **Else** 두 출력이 있습니다. 필터를 통과한 이벤트는 **If**로, 통과하지 못한 이벤트는 **Else**로 이어집니다. 분기를 선택하지 않고 필터에서 그린 연결은 **If**를 따릅니다. Snapshot은 출력이 있는 유일한 액션으로, 그 뒤에 연결된 액션은 Snapshot이 찍은 스냅샷을 받습니다. 다른 액션은 종단점입니다.

[노드](nodes.md)는 모든 노드의 필드와 제한을 나열합니다.

## 이벤트

탐지는 이벤트를 만들고, 그래프를 따라 흐르는 것은 이벤트입니다. 추론 서비스는 처리한 모든 프레임에 대해 탐지 결과를 보고합니다. 레이블, 경계 상자, 신뢰도, 추적 ID가 여기에 포함됩니다. API는 한 프레임의 탐지를 레이블별로 묶어 레이블마다 하나의 이벤트를 만들고, 레이블 이름을 따서 이벤트 이름을 정합니다. `helmet`은 `HELMET_DETECTED`가 되고 `space-empty`는 `SPACE_EMPTY_DETECTED`가 됩니다. 모델 매니페스트로 레이블의 이벤트 이름을 바꾸거나 억제할 수 있습니다. 이벤트 종류의 고정 목록은 없으며, 설치한 모델이 어휘를 정의합니다.

이벤트는 종류, 카메라, 타임스탬프, 프레임 크기, 이벤트를 만든 탐지들, 개수를 담습니다. 필터는 이 필드들을 살핍니다. Zone은 각 탐지의 중심점을 다각형과 비교하고, Class는 레이블을, Size는 상자 면적을 검사하며, If / Else는 종류, 클래스, 개수 또는 최고 신뢰도를 비교합니다.

세 가지 제한 장치가 이벤트 폭주를 억제합니다.

- **이벤트 재알림 대기 시간**(`EVENT_COOLDOWN_SECONDS`, 기본 2초)은 같은 카메라에서 같은 종류의 이벤트가 반복되면 그래프에 들어가기 전에 버립니다.
- **Debounce**는 원하는 위치에 두는 필터로, 자체 시간 창을 가집니다.
- **Alert 재알림 대기 시간**은 Alert 액션의 필드로, 알림 기록에만 적용됩니다.

이벤트와 제한 장치의 상태는 API 프로세스의 메모리에 있습니다. API가 재시작되면 초기화되며 API 복제본 간에 공유되지 않습니다.

## 카메라와 실행

워크플로의 모든 Camera 노드는 상태를 가진 카메라 레코드가 됩니다.

| 상태 | 의미 |
| --- | --- |
| **Pending**(대기 중) | 워크플로가 실행 중이지만 추론 서비스가 아직 스트림을 확인하지 않음 |
| **Active**(활성) | 프레임이 처리되고 있음 |
| **Error**(오류) | 스트림이 실패함. API가 점차 늘어나는 간격으로 재시도함 |
| **Off**(꺼짐) | 워크플로가 중지됨 |

모니터는 같은 상태를 **Starting**, **Live**, **Error**, **Off**로 표시하고, API는 `pending`, `active`, `error`, `disabled`로 보고합니다.

워크플로를 시작하면 MediaMTX에 카메라마다 경로 하나를 노출하도록 요청하고, 추론 서비스에 카메라마다 워커 하나를 시작하도록 요청합니다. 각 시작은 리비전 번호가 붙은 *실행*이므로, 중지되었거나 재구성된 카메라가 이전 실행에서 늦게 도착한 메시지로 되살아나지 않습니다. API의 조정 루프가 30초마다 원하는 상태를 다시 전파하며, 어떤 서비스가 재시작되더라도 카메라가 복구되는 것은 이 덕분입니다.

실행 중인 워크플로의 탐지 설정을 바꾸면 그 자리에서 적용됩니다. 카메라의 소스를 바꾸면 해당 워커가 재시작됩니다.

[카메라](cameras.md)는 소스 유형과 MediaMTX가 이를 처리하는 방식을 다룹니다.

## 모델

모델은 `models/`에 놓인 ONNX 파일과 매니페스트입니다. 매니페스트는 모델이 만들어 내는 레이블을 선언하고, 선택적으로 표시 이름, 권장 신뢰도 임계값, 이벤트 재정의를 담습니다. API는 실행 시점에 모델 번들을 발견하고, Detect 노드는 그 카탈로그에서 모델을 고릅니다.

탐지는 카메라 프레임 속도가 아니라 Detect 노드가 정한 속도(**Checks per second**, 초당 검사 횟수)로 실행됩니다. 객체는 검사 사이에도 추적되므로, 선 통과나 체류처럼 동일성이 필요한 필터가 한 객체를 시간에 따라 따라갈 수 있습니다.

[모델](models.md)은 매니페스트 형식과 내보내기를 다룹니다.

## 자격 증명

외부 서비스(Telegram, Discord, 이메일, MQTT, Slack)와 통신하는 액션은 토큰을 직접 보관하지 않고 자격 증명을 참조합니다. 자격 증명은 암호화되어 저장되고, 이름과 비밀이 아닌 요약만 표시되며, 전달 시점에 해석되므로 토큰을 교체하면 즉시 반영됩니다.

[액션과 통합](actions-and-integrations.md)은 각 유형을 다룹니다.

## 에디션

Community 에디션은 저장소의 `ee/` 디렉터리 밖에 있는 모든 것이며 Apache-2.0으로 라이선스됩니다. Enterprise 에디션은 Count, Line crossing, Dwell 필터와 Slack 액션을 추가하며, 이들은 라이선스 키가 구성되기 전까지 노드 팔레트에 잠금 아이콘과 함께 표시됩니다. 두 에디션은 같은 이미지로 배포됩니다. 자세한 내용은 [Enterprise 에디션](enterprise.md)에 있습니다.
