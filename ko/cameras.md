# 카메라

Camera 노드는 LookSee에 프레임이 어디서 오는지 알려 줍니다. MediaMTX가 모든 소스를 수신해 카메라마다 하나의 RTSP 경로로 추론 서비스에 노출하고, 같은 스트림을 실시간 모니터용으로 WebRTC를 통해 브라우저에 제공합니다.

## 소스 유형

| 소스 유형 | 필드 | 수신 방식 |
| --- | --- | --- |
| **RTSP** | `rtsp://` 또는 `rtsps://` URL | MediaMTX가 필요할 때 스트림을 가져옵니다. 대부분의 IP 카메라와 NVR. |
| **RTMP** | `rtmp://` 또는 `rtmps://` URL | MediaMTX가 필요할 때 스트림을 가져옵니다. |
| **SRT** | `srt://` URL | MediaMTX가 필요할 때 스트림을 가져옵니다. |
| **Browser webcam** | 없음 | 송출 모드. Studio가 브라우저의 카메라를 WebRTC(WHIP)로 MediaMTX에 송출합니다. |
| **WHEP** | `http://`, `https://`, `whep://`, `wheps://` URL | MediaMTX가 원격 WebRTC 엔드포인트에서 가져옵니다. |
| **File** | 자산 키 | 자산 라이브러리의 비디오를 로컬에 캐시하고 라이브 스트림처럼 반복 재생합니다. |

풀 소스는 필요할 때만 동작합니다. MediaMTX는 추론 서비스나 브라우저가 경로를 요청할 때 업스트림에 연결하고, 마지막 수신자가 떠난 뒤 10초가 지나면 연결을 끊습니다. 업스트림의 자격 증명은 `rtsp://user:password@192.168.1.30:554/stream1`처럼 URL에 넣으며, 서버 밖으로 나가지 않습니다.

## RTSP, RTMP, SRT

카메라나 인코더가 송출하는 URL을 입력합니다. 일반적인 구성에 대한 참고 사항:

- 메인 스트림보다 카메라의 서브스트림(720p 이하)을 사용합니다. 탐지는 초당 몇 프레임으로 실행되므로 4K의 이점은 없고 디코딩에 CPU만 소모됩니다.
- H.264는 어디서나 디코딩됩니다. H.265는 탐지에는 문제없지만 브라우저가 WebRTC로 재생하지 못하므로, 알림은 계속 도착해도 실시간 모니터는 검게 남습니다.
- MediaMTX는 RTSP를 TCP로 가져옵니다. 카메라가 UDP만 제공하면 TCP를 지원하는 릴레이 뒤에 둡니다.
- 다른 네트워크의 카메라는 LookSee가 실행되는 머신에서 접근할 수 있어야 합니다. 브라우저는 카메라에 직접 연결하지 않습니다.

## 브라우저 웹캠

소스 유형이 **Browser webcam**인 카메라에는 URL이 없습니다. 워크플로가 실행 중이고 편집기나 모니터가 열려 있으면 Studio가 웹캠 사용 권한을 요청하고 브라우저에서 MediaMTX로 송출합니다. 모니터에는 이런 카메라를 위한 **Publish**(송출)와 **Stop publish**(송출 중지) 버튼이 표시됩니다. 탭을 닫으면 스트림이 멈추고, 브라우저가 다시 송출할 때까지 카메라는 **Pending**으로 돌아갑니다.

브라우저는 `WEBRTC_HOST_IP`의 포트 `8889`로 송출하며 ICE 포트 `8189/udp`가 열려 있어야 합니다. [네트워킹](#네트워킹)을 참고하십시오.

## 비디오 파일

**File** 카메라는 자산 라이브러리의 객체를 반복 재생하므로, 녹화 영상으로 워크플로를 시험할 때 유용합니다. 자산 라이브러리는 `S3_*` 변수로 구성하는 S3 호환 버킷입니다. Cloudflare R2를 기준으로 만들어졌으며 MinIO나 다른 S3 엔드포인트에서도 동작합니다. 버킷이 구성되지 않으면 **Assets**(자산) 선택기와 `/assets` 엔드포인트가 비활성화됩니다.

파일은 Studio나 `POST /assets`로 업로드합니다. 시작 시 API가 객체를 미디어 캐시 볼륨에 내려받고, MediaMTX가 이를 읽어 ffmpeg로 파일을 반복 재생합니다. 객체 키는 ffmpeg 명령 안에 들어가기 때문에 영문자, 숫자, `.`, `_`, `-`, `/`만 허용됩니다.

## MediaMTX

MediaMTX는 `docker/mediamtx/mediamtx.yml`의 구성으로 `mediamtx` 서비스로 실행됩니다. LookSee는 포트 `9997`의 제어 API로 경로를 관리하고, 파일 자체는 프로토콜과 인증만 설정합니다.

- RTSP는 `8554`에서 TCP로, WebRTC는 `8889`에서 ICE `8189/udp`와 함께 동작합니다. RTMP, HLS, SRT 리스너는 꺼져 있지만, RTMP나 SRT 업스트림에서 가져오는 데는 영향이 없습니다.
- `MTX_MEDIA_USER`와 `MTX_MEDIA_PASSWORD`로 정의된 사용자 하나가 읽기와 송출을 할 수 있습니다. 추론 서비스와 브라우저가 이 사용자를 씁니다. Studio는 재생을 위해 이 자격 증명을 브라우저에 넘기므로, 백엔드 시크릿이 아니라 신뢰할 수 있는 네트워크의 접근 정보로 취급합니다.
- 제어 API는 루프백과 사설 네트워크 범위에 인증 없이 열려 있으며, compose는 이를 `127.0.0.1`에 바인딩합니다.

모든 카메라의 경로 이름은 카메라 ID입니다. 추론 서비스는 `rtsp://mediamtx:8554/<camera id>`를 읽고, 브라우저는 `http://<WEBRTC_HOST_IP>:8889/<camera id>/whep`을 재생합니다.

## 네트워킹

실시간 영상은 WebRTC로 브라우저에 도달하며, 웹 포트 하나를 여는 것만으로는 부족합니다.

| 포트 | 프로토콜 | 연결 주체 |
| --- | --- | --- |
| `8889` | TCP | 브라우저. WebRTC 시그널링과 재생(WHEP), 웹캠 송출(WHIP) |
| `8189` | UDP | 브라우저. WebRTC 미디어(ICE) |
| `8554` | TCP | **Browser webcam** 카메라의 경로로 RTSP를 푸시하는 인코더(송출 모드). 풀 소스에는 필요 없음 |

`WEBRTC_HOST_IP`는 브라우저가 접근할 수 있는 주소여야 합니다. 노트북에서는 `127.0.0.1`, 서버에서는 LAN 주소입니다. MediaMTX가 이 값을 ICE 후보로 알리므로, 값이 잘못되면 모니터가 연결된 뒤 **Connection disconnected**(연결 끊김)를 표시합니다. 리버스 프록시와 TLS는 [배포](deployment.md)에서 다룹니다.

## 카메라 상태

모니터는 카메라 이름 옆에 상태 배지를 표시하고, 워크플로 목록은 워크플로별로 상태를 표시합니다.

- **Pending**(대기 중, 모니터에서는 **Starting**): 워커가 시작 중입니다. 풀 소스는 보통 몇 초 안에 첫 프레임이 도착하며, 추론 서비스는 `FIRST_FRAME_TIMEOUT_SECONDS`(30초)가 지나면 포기하고 오류를 보고합니다.
- **Active**(활성, 모니터에서는 **Live**): 프레임이 흐르고 있습니다.
- **Error**(오류): 스트림이 실패했거나 30초 동안 멈췼습니다. API는 30초에서 시작해 5분까지 두 배씩 늘어나는 간격으로 재시도합니다. 이유는 모니터와 `api`, `inference` 로그에 표시됩니다.
- **Off**(꺼짐): 워크플로가 중지되었습니다.

[문제 해결](troubleshooting.md)에 **Pending**과 **Error**의 흔한 원인이 정리되어 있습니다.
